# Video Reference Share Service - MVP設計書

## 1. 概要

YouTube やニコニコ動画の URL をまとめ、コメント付きで 1 ページに集約し、共有 URL で閲覧できる Web サービスを提供する。

主な利用シーンは以下を想定する。

- DTM・作編曲・演奏依頼時のリファレンス共有
- おすすめ動画のまとめ共有
- 制作依頼時の参考資料ページ化

本 MVP では、**「複数の動画を、コメント付きで 1 ページにまとめて共有できること」** を最小価値とする。

---

## 2. 目的

単なるリンク集ではなく、動画ごとに意図や補足を添えて、文脈を持った共有を可能にする。

ユーザーが得られる価値は次の通り。

- 複数の参考動画を 1 つの URL で共有できる
- 各動画について「なぜ参考なのか」をコメントで残せる
- 受け手がページ内でそのまま視聴できる

---

## 3. MVP スコープ

### 3.1 実装対象

- リスト作成
- リスト名の入力
- 説明文の入力（任意）
- YouTube / ニコニコ動画 URL の追加
- 動画の埋め込み表示
- 各動画への備考コメント入力
- 動画の並び替え
- 共有 URL の発行
- 発行した URL での閲覧

### 3.2 MVP では実装しないもの

- ユーザー登録 / ログイン
- お気に入り
- 閲覧者コメント
- いいね
- 限定公開
- 検索機能
- SNS 自動投稿連携
- OGP カスタマイズ
- タイル表示切替
- タイムスタンプ付きコメント

---

## 4. 想定ユーザー

### 4.1 メインターゲット

- DTM ユーザー
- ボカロP
- 楽曲制作者
- 演奏依頼・ミックス依頼を行う人

### 4.2 サブターゲット

- おすすめ動画をまとめたい一般ユーザー
- 動画コンテンツをテーマごとに共有したいユーザー

---

## 5. ユースケース

### 5.1 リファレンス共有

ユーザーは作曲依頼時に、参考にしてほしい楽曲動画を 5 本ほど登録し、それぞれに「イントロの雰囲気」「サビの抜け感」などのコメントを記載して共有する。

### 5.2 おすすめ動画まとめ

ユーザーはテーマに沿ったおすすめ動画を 1 ページにまとめ、X などで共有する。

---

## 6. 画面設計

### 6.1 画面一覧

MVP では以下の 2 画面で構成する。

1. 作成・編集画面（Editor）
2. 閲覧画面（Viewer）

---

### 6.2 作成・編集画面（Editor）

#### 画面目的

- リストの作成
- 動画の追加
- コメントの入力
- 並び順の調整
- 共有リンクの取得

#### 画面構成

```text
[ リスト名入力 ]
[ 説明文入力（任意） ]

[ URL入力欄 ] [ 追加 ]

----------------------------------
[ 動画ブロック ]
  [ 埋め込み動画 ]
  [ 備考コメント入力欄 ]
  [ ↑ ] [ ↓ ] [ 削除 ]
----------------------------------

（動画ブロックが縦に並ぶ）

[ 共有リンクをコピー ]
```

#### UI 方針

- 1 カラムの縦並びとする
- 動画追加から共有まで、できるだけ 1 画面内で完結させる
- 余計なモーダル遷移は入れない
- コメントは 1〜3 行程度の軽い入力を想定する

---

### 6.3 閲覧画面（Viewer）

#### 画面目的

- 共有されたリストを閲覧する
- 動画をその場で視聴する
- 各動画のコメントを確認する

#### 画面構成

```text
リスト名
説明文

----------------------------------
[ 埋め込み動画 ]
コメント
----------------------------------

（動画ブロックが縦に並ぶ）
```

#### UI 方針

- 編集 UI は表示しない
- 動画視聴とコメント確認に集中できるシンプルな構成にする
- PC / スマホともに 1 カラムとする

---

## 7. UX 方針

### 7.1 基本方針

このサービスは「動画一覧」ではなく、**意図を伝える共有ページ**である。
そのため、一覧性よりも以下を優先する。

- 順番が伝わること
- コメントが読みやすいこと
- 動画がその場ですぐ見られること

### 7.2 表示形式

- MVP では縦 1 列固定
- 横 2〜3 列のタイル形式は採用しない

理由は以下の通り。

- コメントの可読性が落ちる
- 動画サイズが小さくなる
- 順番や文脈が伝わりにくくなる
- スマホで結局 1 列に戻る

---

## 8. 機能要件

### 8.1 リスト作成

- リスト名を入力できること
- 説明文を入力できること（任意）
- 保存後に共有用 URL が生成されること

### 8.2 動画追加

- YouTube / ニコニコ動画 URL を入力できること
- 入力された URL を解析し、埋め込み表示できること
- 対応外 URL はエラー表示すること

### 8.3 動画コメント

- 各動画に備考コメントを保存できること
- コメントはプレーンテキストで扱うこと

### 8.4 動画並び替え

- 上へ / 下へボタンで順番を変更できること
- 表示順が保存されること

### 8.5 共有

- 閲覧用 URL をコピーできること
- 閲覧者はログイン不要でページを見られること

---

## 9. 非機能要件

### 9.1 パフォーマンス

- 一覧ページの初期表示は 3 秒以内を目標とする
- 動画本体の読み込み速度は外部サービスに依存する

### 9.2 可用性

- 一般的な個人開発レベルの可用性を満たす
- サービス停止時にデータ消失しない構成とする

### 9.3 セキュリティ

- コメント欄は HTML を解釈せず、エスケープして表示する
- URL は許可ドメインのみ受け付ける
- 不正スクリプトを埋め込めないこと

---

## 10. 対応プラットフォーム仕様

### 10.1 YouTube

#### 入力 URL 例

- `https://www.youtube.com/watch?v=VIDEO_ID`
- `https://youtu.be/VIDEO_ID`

#### 埋め込み URL 例

- `https://www.youtube.com/embed/VIDEO_ID`

### 10.2 ニコニコ動画

#### 入力 URL 例

- `https://www.nicovideo.jp/watch/sm12345678`

#### 埋め込み URL 例

- `https://embed.nicovideo.jp/watch/sm12345678`

### 10.3 バリデーション方針

- YouTube / ニコニコ動画の既知 URL パターンのみ許可
- 解析できない URL は登録不可

### 10.4 URL パーサ仕様

| platform | 受け付ける URL 例 | 抽出対象 | embed_url 生成ルール |
| --- | --- | --- | --- |
| youtube | `https://www.youtube.com/watch?v=VIDEO_ID` | `v` クエリの値 | `https://www.youtube.com/embed/{video_id}` |
| youtube | `https://youtu.be/VIDEO_ID` | パス末尾の値 | `https://www.youtube.com/embed/{video_id}` |
| niconico | `https://www.nicovideo.jp/watch/sm12345678` | `/watch/` 以降の値 | `https://embed.nicovideo.jp/watch/{video_id}` |

#### パーサの判定手順

1. URL を正規化して scheme / host / path / query を分解する
2. host が YouTube 系かニコニコ動画かを判定する
3. URL パターンに応じて `video_id` を抽出する
4. `platform` と `embed_url` を確定する
5. どのパターンにも一致しない場合はエラーとする

#### バリデーション補足

- `video_id` が空文字になる URL は不正とする
- YouTube は MVP では通常動画 URL のみ対象とし、`shorts` や `playlist` は対象外とする
- ニコニコ動画は MVP では `watch` URL のみ対象とする
- 受け取った URL 文字列は保存前に trim する

## 11. データ設計

MVP では、以下の 2 エンティティを基本とする。

### 11.1 List

| 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| id | string | 必須 | リスト ID |
| title | string | 必須 | リスト名 |
| description | string | 任意 | 説明文 |
| created_at | string | 必須 | 作成日時 |
| updated_at | string | 必須 | 更新日時 |

### 11.2 Video

| 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| id | string | 必須 | 動画ブロック ID |
| list_id | string | 必須 | 紐づくリスト ID |
| platform | string | 必須 | youtube / niconico |
| video_url | string | 必須 | 元 URL |
| video_id | string | 必須 | 動画 ID |
| embed_url | string | 必須 | 埋め込み URL |
| comment | string | 任意 | 備考コメント |
| sort_order | number | 必須 | 表示順 |
| created_at | string | 必須 | 作成日時 |
| updated_at | string | 必須 | 更新日時 |

## 12. API 設計

MVP では REST 形式を前提とする。

### 12.1 リスト作成

`POST /api/lists`

#### request

```json
{
  "title": "参考曲まとめ",
  "description": "サビの抜け感を参考にしたい曲です"
}
```

#### response

```json
{
  "id": "list_xxxxx",
  "share_url": "/p/list_xxxxx"
}
```

---

### 12.2 リスト取得

`GET /api/lists/{id}`

#### response

```json
{
  "id": "list_xxxxx",
  "title": "参考曲まとめ",
  "description": "サビの抜け感を参考にしたい曲です",
  "videos": [
    {
      "id": "video_xxxxx",
      "platform": "youtube",
      "video_url": "https://youtu.be/xxxxx",
      "embed_url": "https://www.youtube.com/embed/xxxxx",
      "comment": "イントロの雰囲気が理想",
      "sort_order": 1
    }
  ]
}
```

---

### 12.3 動画追加

`POST /api/lists/{id}/videos`

#### request

```json
{
  "video_url": "https://youtu.be/xxxxx",
  "comment": "サビの音圧感が参考"
}
```

#### request example: niconico

```json
{
  "video_url": "https://www.nicovideo.jp/watch/sm12345678",
  "comment": "歌い出し前の空気感を参考にしたい"
}
```

#### response

```json
{
  "id": "video_xxxxx"
}
```

---

### 12.4 動画更新

`PATCH /api/lists/{id}/videos/{video_id}`

#### request

```json
{
  "comment": "Aメロの質感も参考になる",
  "sort_order": 2
}
```

### 12.6 動画データ例

#### YouTube

```json
{
  "id": "video_xxxxx",
  "platform": "youtube",
  "video_url": "https://youtu.be/xxxxx",
  "video_id": "xxxxx",
  "embed_url": "https://www.youtube.com/embed/xxxxx",
  "comment": "イントロの雰囲気が理想",
  "sort_order": 1
}
```

#### ニコニコ動画

```json
{
  "id": "video_sm12345678",
  "platform": "niconico",
  "video_url": "https://www.nicovideo.jp/watch/sm12345678",
  "video_id": "sm12345678",
  "embed_url": "https://embed.nicovideo.jp/watch/sm12345678",
  "comment": "ブレイク前の展開を参考にしたい",
  "sort_order": 2
}
```

---

### 12.5 動画削除

`DELETE /api/lists/{id}/videos/{video_id}`

## 14. インフラ構成案

MVP 時点では、コストと開発速度を優先し、以下の構成を想定する。

- フロントエンド: Next.js
- ホスティング: Vercel
- API: Next.js Route Handler または Server Actions
- DB: DynamoDB
- IaC: AWS CDK

### 14.1 採用理由

- 動画本体を保持しないため軽量構成で十分
- DynamoDB で低コスト運用しやすい
- AWS / CDK スキルを活かせる
- MVP の開発速度を上げやすい

---

## 16. リスク・課題

### 16.1 外部動画サービス依存

- 埋め込み禁止の動画は再生できない可能性がある
- 非公開 / 削除済み動画は表示不可になる

### 16.2 認証なし運用

- MVP では編集権限の扱いが弱い
- 本運用時には編集トークンやログイン機能を検討する必要がある

### 16.3 利用規約確認

- YouTube / ニコニコ動画の埋め込み利用規約に従うこと
- 動画データ自体の保存・再配布は行わないこと

## 20. 結論

本 MVP は、動画を並べるだけのサービスではなく、**コメント付きで文脈を共有するためのリファレンスページ作成ツール**として設計する。

まずは以下 4 点を最小価値として成立させる。

- リスト名を付けられる
- 動画を埋め込んで視聴できる
- 各動画に備考コメントを残せる
- リンクを共有できる

この最小構成でユーザー価値を検証し、利用実態を見てから拡張機能を追加する。
